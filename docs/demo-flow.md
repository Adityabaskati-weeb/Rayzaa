# Rayzaa Demo Flow

## Goal

The demo should feel like a fraud operations room, not a static model showcase.

## Sequence

### 1. Calm State

Start on the main operations screen with:

- a flowing transaction rail
- current approval/review/block counts
- active graph in low-alert mode
- live map and risk counters

### 2. Suspicious Activity Emerges

Inject a seeded event cluster:

- same device linked to multiple accounts
- abnormal transaction burst
- location jump
- unusual merchant reuse

The transaction tiles should visibly escalate in color and urgency.

### 3. Graph Expansion

Open the fraud graph and reveal:

- connected user nodes
- shared device node
- suspicious merchant hub
- ring-risk highlighting

Narration: the system is not just flagging a single transaction, it is identifying a coordinated pattern.

### 4. Explainability Moment

Open the explanation drawer:

- top contributing features
- SHAP-style contribution chart or ranked factors
- analyst brief in plain English

Narration: Rayzaa translates technical signals into operational decisions.

### 5. Verification Trigger

If the transaction crosses the high-risk band, trigger a simulated verification step:

- voice check status
- device revalidation status
- trust adjustment

Narration: secondary verification protects against false blocks while preserving security posture.

### 6. Analyst Action

Allow the operator to:

- confirm fraud
- override to review
- approve with note
- escalate for KYC/AML

### 7. Feedback Loop

Update a small policy panel:

- false-positive counter
- confirmed fraud counter
- threshold sensitivity indicator

Narration: analyst feedback continuously sharpens system behavior.

## Demo Rule

Always use pre-scripted hero cases for the high-drama sequence. The live stream can be partly random, but the showcase moments should be deterministic.
